# 网页会话生图与导入修复（2026-10-15）

本记录更新此前候选版本的排查状态。当前服务器已部署网页 SDK 执行路径与新会话结果结构兼容；Plus 账号完成真实出图验证。随后 Pro 会话也已补齐，但其单账号生图测试仍返回 404，不能认为所有账号均已恢复。

## 会话字段与证据边界

- 用户此前提供的 `/api/auth/session` JSON 同时包含 `accessToken` 和 `sessionToken`。本实现使用前者调用接口，并将后者写入网页登录 Cookie；这不是聊天记录，也不是要求导入全部浏览器数据。
- 目前的原生网页路径明确要求登录会话。原生 SDK 加网页会话的组合在指定 Plus 上成功，不代表已证明所有反代都必须有该字段，或所有 404 都由缺少该字段造成。
- 默认选号优先限定为带完整会话的可用账号；Pro 会话更新后，Plus 与 Pro 都进入候选集合。显示“正常”以及进入候选集合，均不能代替生图验证。
- 新会话文档使用平铺 `messages`；此前只读取 `mapping` 会漏掉后台已经完成的图片。本次兼容两种结构与 ISO 时间。

## 已完成验证

- 相关 Python 回归 75 项通过。
- 隔离完整 HTTP 文生图实际返回 PNG，耗时约 37 秒；图生图实际返回 PNG，耗时约 56 秒。
- 部署后一次公网同步生图在约 125 秒返回 524，后台记录了最终沙盒图片事件。该事件不能代替客户端收到图片，不能把此前 404 归因于这次超时。
- 旧客户站未重建或重启。账号身份、API 密钥与原配置在部署时核对保留。

## Session JSON 导入遗漏

账号页此前虽然接收完整 JSON，但实际仅调用令牌导入，丢弃 `sessionToken`。因此不能仅凭存储缺字段，认定用户没有粘贴完整 JSON。

现在页面提交 `access_token`、`sessionToken`（提供时）和 `source_type=web`，不把其他 JSON 个人资料一并保存。增加格式及长度检查，JSON 解析错误使用固定提示，避免回显凭据片段。后端既有逻辑将 `sessionToken` 保存为 `web_session_token`。

仓库只有前端构建产物，本次新增带内容摘要的 JS 文件并更新账号页四处入口，避免继续加载旧缓存。旧文件保留以兼容已打开的页面。

- 验证命令：`node tests/test_session_import.mjs`；覆盖完整会话传递、旧格式兼容、非法输入和错误脱敏。
- 发布镜像：`local/chatgpt2api-image:session-import-ca69a8b4e99c`，同时更新 `latest`。
- 在线服务仅原子替换五个静态文件，未重启，不打断现有生图。下一次重建使用同内容的新镜像。
- 脱敏发布验证：`/tmp/image-pro-sse-repair-lfl9h1ji/session-import-fix/verification.json`。
- 刷新账号页后重新导入各账号自己的完整 JSON。历史已丢弃的 `sessionToken` 无法从访问令牌或 SSE 还原。

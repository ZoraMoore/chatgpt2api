# 原生首轮生图与最终图片

`image.example.com` 使用原生首轮生图流程。每次正常生成只提交一次上游 `conversation` 请求；是否执行代码、查看图片或继续处理，由上游在这一轮中决定。

## 请求与返回

- 默认 `size`、`quality` 为 `auto` 时，原始提示词逐字保留；用户明确设置的尺寸和质量仍作为输出要求传递。
- 参考图按网页协议上传、等待文件处理完成，并随原始提示词提交。保留 `gpt-6-thinking`、`thinking_effort=extended` 等现有网页参数。
- 首轮直接返回图片时正常交付，不要求调用 Python、容器或其他校图工具。
- 上游在首轮自行调用工具并提供最终沙盒图片时，读取完整事件流和最终消息，下载该最终文件。
- 对上游实际声明的最终文件保留路径、图片格式和完成状态检查；正常的生成超时、网络错误和下载失败仍按原错误机制处理。
- 结果轮询仅查询已有生成任务；用户手动续轮询沿用已有会话，不会提交新的生成提示词。

## 执行记录

任务接口保留真实事件对应的阶段进度和有界历史。执行摘要只记录工具计数、`code_tool_after_image`、`skipped_mainline`、`thought_message_count`、`stream_complete`、`upstream_model_slug` 和 `result_source`。

`result_source=image_tool` 表示原生图片工具产物，`sandbox` 表示上游最终消息指定的沙盒图片，`unavailable` 表示未取得结果。它们用于描述实际执行过程，不对图片做额外质量判定，也不要求必须校图。

服务端不执行上游返回的 Python、Shell 或 DIL 代码；不记录或公开推理原文、工具代码和账号凭据。历史日志保留当时的原始记录。

## 配置和验证

参考图生成预算由 `image_edit_generation_timeout_secs` 控制，默认 600 秒；普通生图使用 `image_generation_timeout_secs`，结果轮询使用 `image_poll_timeout_secs`。

当前版本已删除强制校图开关、未校图拒绝交付分支、追加复核状态、预设修正版路径和旧质量标签。

回归验证覆盖首轮仅返回图片、三种轮询交付路径、首轮自然调用工具、最终文件下载、断流处理、路径校验、任务权限和执行摘要脱敏。

生图恢复后，使用[模型字段测试脚本](image-protocol-test.md)实测上游 SSE 与会话查询响应中的 `resolved_model_slug`；调用失败或断流不会被判成字段缺失。

## 发布验证边界

多实例应独立保存配置和数据。上线前核对目标实例、前端版本和实际请求结果，记录一次请求的终态并下载验证文件。状态页、前置接口成功及单测不等同于真实出图成功。个人部署的域名、账号、镜像、容器、调用结果与时间记录留在本地。

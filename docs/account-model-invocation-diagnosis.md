## HAR 可以证明的内容

附件 `chatgpt.com2 10 15.har` 的第 8 条请求（从 0 计数）是成功的 `POST /backend-api/f/conversation`，请求模型为 `gpt-6-thinking`。第 48 条会话查询的响应为 base64 编码，解码后可以读取到 `resolved_model_slug=gpt-6-thinking`。

主请求的 `_eventSourceMessages` 只有事件名称、标识和时间，没有事件正文；其响应正文也是空的，因此无法用它完整回放 SSE。第 15、19 条 Sentinel prepare/finalize 属于另一组校验：其最终令牌与第 8 条请求头中的令牌不同，不能把它们拼成同一次成功请求。

## 已落到本地的修正

`utils/pow.py` 的 `_pow_generate` 原先使用 SHA3-512，且 `build_proof_token` 缺少 `~S` 成功后缀。当前网页 SDK 与隔离浏览器生成的校验结果使用 FNV 混合哈希；浏览器样本按该算法校验通过，按 SHA3-512 校验不通过。

本地修正复用现有 `SentinelTokenGenerator._fnv1a_32`，补齐成功后缀，使用实际计算耗时，并对上游种子、难度、配置大小、尝试次数和 3 秒计算预算加边界检查。参考来源是当次读取的 [OpenAI Sentinel SDK](https://chatgpt.com/sentinel/20260219f9f6/sdk.js) 和上述浏览器运行结果。

`tests/test_pow_protocol.py` 的 9 项测试在当前部署镜像的独立容器中通过，容器禁用网络并使用临时数据目录。测试覆盖独立 JavaScript 黄金向量、难度边界、格式后缀、超时、失败处理和输入边界。

现有 `utils/turnstile.py` 仍存在不执行替换后的指令队列等兼容问题。临时候选解析器仅用于隔离对照，没有作为已完成修复写入生产代码；输出非空不等于上游接受该结果。

# 账号模型调用排查方法

本文提供通用诊断方法，不包含个人账号、历史请求样本或实际部署状态。

## 分层确认

- `/version` 和健康接口只能证明网关进程可访问。
- 账号资料和模型目录成功，不等于该账号能够完成图片生成。
- 区分生成 POST 之前的拒绝、SSE 中的工具错误、图片轮询超时以及最终文件下载失败。
- `Model not found` 等文案可能来自不同阶段，不能只凭文案认定套餐、模型或出口是根因。

## 对照方法

使用授权测试账号，每次明确发起一个请求。对照浏览器和服务端的账号上下文、浏览器身份、设备标识、请求阶段及终态事件；保留脱敏的状态码和阶段信息，不公开原始 HAR、Cookie、Token、账号标识或提示词。

协议修正需先有可复现测试，并验证异常处理、输入长度和执行预算。查到某项协议差异不等于已经证明它导致了线上故障。

## 完成条件

用同一请求取得终态结果，下载并验证有效图片，才可宣称该路径恢复。健康检查、前置接口成功或候选代码单测通过均不能替代此验证。相关通用说明见 [HAR 对照](latest-har-alignment-20261015.md) 和 [出口时区](egress-timezone.md)。

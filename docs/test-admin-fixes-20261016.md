# Image 测试站管理修复

仅发布到 `https://image.liunx.me/`，镜像为 `local/chatgpt2api-image:admin-fixes-20261016`。主站 `api.liunx.me` 的容器、启动时间和运行镜像保持不变。测试站 2 个账号身份、密钥、配置文件、挂载及 4 个工作线程限制校验保留。

## 日志时间

日志管理的时间列明确标注“北京时间”。新日志存 UTC ISO 时间，读取时将旧的无时区 UTC 时间和新时间统一转换为 Asia/Shanghai，日期筛选也以北京时间日期为准。历史日志文件不批量改写，删除日志的 ID 保持稳定。

## 账号操作

每个账号列表行的“操作”打开账号管理面板；勾选多个账号后可使用“批量操作”，最多 20 个，支持跨页选择。

- **清理图像空间**：带入所选账号，仍先预览、再确认，将快照中的图片移入最近删除。
- **每日自动清理**：每个账号独立开关，默认关闭；开启后 24 小时首次执行，此后每 24 小时一次，仅清理 7 天前图片。采用实际上游的 record_creation_time / file_upload_time 等创建字段，不以修改时间判断；未知创建时间的图片保留。
- **手动刷新 Access Token**：明确调用 OAuth refresh_token 授权，不等同于刷新额度。缺少 Refresh Token 的账号显示原因并禁用单账号按钮。
- **到期自动刷新**：默认开启，可按账号关闭。展示的到期时间固定使用北京时间，JWT exp 优先，无法解析 JWT 时使用导入的 expires_at。

后台继续按设置中的账号刷新间隔检查，提前 24 小时刷新 Access Token，保留既有每 3 天 Refresh Token 保活及错误退避；关闭到期自动刷新也会停止该账号的自动保活。自动清理的下次时间和状态持久化，重启不会当天重复提交。禁用、在途或已移除账号跳过；扫描后再次核实开关和账号状态再提交删除。

## Sub2API 完整导入

设置页受保护导出将完整 credentials 转成账号对象保存，包括 access_token、refresh_token、id_token、expires_at、client_id、身份、套餐及其他凭据字段。非凭据来源元数据保存在 sub2api 字段；本地 JSON 文件导入也支持嵌套 credentials 格式。

同一用户和工作区的不同 Token 合并到现有账号，保留本地代理、统计与操作开关；旧 iat 的导入不能覆盖已保存的新凭据。身份不足时不会仅凭邮箱猜测合并。刷新使用来源 client_id（缺省沿用现有 OAuth 客户端），原子写回轮换的 Access Token、Refresh Token、ID Token 和到期时间。账号操作接口使用稳定引用，返回状态而非凭据。

测试站现有 2 个账号原先都缺少 refresh_token，需要从 Sub2API 重新完整导入才能自动或手动续期；本次无法对这两个账号执行真实 OAuth 续期。已有网页 sessionToken 不等同于 OAuth refresh_token。

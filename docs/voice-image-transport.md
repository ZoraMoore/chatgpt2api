## 请求与交付

每个任务使用所选账号自己的 HTTP 会话、工作区与设备标识。参考图先走原有上传流程，随后作为附件加入语音 `relay_message`。语音会话通过 `/realtime/wm` 建立，音轨为零 PCM，时区固定为 `America/Los_Angeles` 并自动计算夏令时偏移。

## 断连诊断与关闭修复

会话停止通过事件协作唤醒，不再取消可能正在清理连接的 runner。关闭由会话线程统一执行，直接调用 `pc.close()` 结束 SCTP，避免断链后额外发送数据通道重配置消息。HTTP 握手仍有 30 秒上限，返回后再次检查停止标志，禁止关闭期间提交文字。

每次会话生成独立诊断编号，记录阶段、ICE、DTLS、数据通道状态、事件计数和首次失败的异常类型，不记录异常原文、凭据、SDP 或提示词。管理日志失败记录的 `image_execution[].voice_transport` 与容器日志中的 `session_id` 对应；后续清理异常不能覆盖首次故障。

旧版本在新增的并发关闭回归中可复现清理协程被取消，修复版本通过。相关回归 56 项及额外的 40 会话同时失败关闭测试通过；后者为模拟传输，不能作为真实上游 40 并发容量证明。隔离环境的真实 1、2、4 并发共 7 次调用均下载到有效 PNG，未观察到主站账号重叠使用。

额外 8 并发测试中 7 次成功、1 次达到测试专用的 200 秒等待上限；超时时 ICE 为 completed、Peer 为 connected、数据通道为 open，并已正常清理。该轮观察到抽取账号与主站在途任务重叠，无法作为无干扰的容量结论，也不能据此断言重叠导致超时。测试站保留工作线程上限 4、每账号并发 1；生产超时配置未修改。所有测试保持一次文字提交，未发现未处理的异步清理异常。

## 误超时修复（2026-10-16，Image 首发）

本节改动已部署到 Image，版本为 `local/chatgpt2api-image:voice-rootfix-20261016-tpi9uswa`；后续已将同一镜像发布到主站 API，主站标签为 `local/chatgpt2api:voice-rootfix-20261016-cy_evwd6`。前述性能测试及最终图片链接保护机制继续保留。部署入口为 `docker/voice/Dockerfile.rootfix`，以已验证的 Image 镜像为基线，只替换本次涉及的服务模块。

旧完成判定扫描本轮缓存中的全部消息；只要历史分析或语音旁白仍留有 `in_progress`，即使后续最终答复与 spawn 已结束，也可能一直等到生成截止时间。修复版本把状态管理拆入 `services/voice_turn_state.py`：`bidi_voice_fem_message` 标识的语音旁白与 `reasoning_recap` 思考摘要仍保存在缓存中，但不作为产图完成证据、不替换最新工作边界，也不延长工作的静默时间，避免真实工具图片被后置的复述消息阻挡。成功消息不被迟到的进行中快照回退；较早消息的状态补全不会顶替后来的最终答复。

状态另外维护 `last_message_change` 和 `message_revision`，记录所有已接受且确有变化的消息，包括旁白和思考摘要；重复快照、被拒绝的旧状态不推进它们。这组记录用于恢复调度及无图判定的一致性检查，不用来延迟已确认的真实图片完成。

完成仍要求至少收到一次 spawn 结束、没有活动 spawn、没有取消，并保持一秒工作静默。最新的非旁白助手最终答复可以结束本轮，新的工具调用或工作消息会使旧终态失效；已经结束的 spawn 不会被迟到 update 重新激活。没有助手最终答复时，仅兼容明确完成的图片工具输出，并要求没有未完成工作及图片后处理。工具调用、代码、思考内容或旁白本身都不能证明生图成功。

若 spawn 已结束而直播状态仍不完整，`services/voice_reconciliation.py` 配合会话传输进行有界核实：每个生成请求最多通过原账号 HTTP 会话、原会话 ID 读取三次远端会话，单次 GET 不超过五秒，且共用原生成截止时间。相邻读取至少间隔五秒；认证被拒绝后不继续读取。全过程不新建会话、不更换账号、不重发 `relay_message`，也不增加生成超时配置。

后续读取按消息状态调度，减少旁白仍在更新时提前耗尽预算的情况。第一次读取后，如果还没有稳定的无图候选，只有已经出现回复终态提示并且全部消息静默至少两秒，或全部消息持续静默至少十五秒，才允许使用剩余核实机会；出现明确无图候选后，再遵守最小读取间隔做一致性复核。回复终态提示只用于调度 GET，不等于图片已经完成。

远端结果必须包含本次实际提交的用户消息 ID；只使用该消息之后的同轮记录，排除欢迎语、其他会话及后续用户轮次。旧 mapping 格式只沿 `current_node` 的父链读取，不采集其他分支。若快照遗漏已知工具记录、改变其身份或颠倒最新工作边界，或者 GET 期间出现新的工作事件，就放弃这次恢复，继续等待当前请求。恢复得到的文件仍经过原有最终图片选择、下载及图片格式校验，不直接返回中间图片。

核实发现原生最终答复已结束且没有图片产物证据时，返回明确错误：`上游已结束本轮对话，但没有生成可交付的图片；未重复提交生成请求。` 对只有语音转述、没有原生最终答复的情况，要求两次间隔读取的同轮内容保持一致、消息均已完成、工具调用均已配对且无产物，才确认无图；不会因单条“已完成”文字直接判定成功或失败。任何已接受的消息变化，包括 FEM 更新，都会清空此前的无图候选；GET 期间发生的旁白变化也必须在无图确认前检查，不能使用变化前的结果作出失败判定。这里只消除错误等待，不能让上游未执行的图片任务凭空产生结果。

真正仍在生成、工具调用未结束、会话读取失败、远端状态持续更新或无法确认同轮终态时，原生成截止时间仍然生效，仍可能返回 `语音生成等待超时，未重复提交生成请求。` 本轮没有提高上游额度或并发能力，也不承诺固定一分钟出图。诊断记录核实次数、结果类别及必要状态，并以 `reconciliation_probe_ms` 记录每次 GET 相对会话开始的毫秒时间，便于判断是否过早消耗预算；不记录提示词、原始会话正文或凭据。

本轮 157 项针对性回归通过，覆盖历史状态回退、摘要/FEM、同轮恢复、慢消费者、关闭、最终图片选择和已有并发/背压约束。隔离环境正常参考图编辑用时 61.882 秒，完整解码得到 1254×1254 PNG。另一个故意要求只描述图片的请求在 32.865 秒返回 `no_image_generated`，通过两次原会话一致读取确认没有产物；这属于正确失败，不能计为生图成功。测试也观察到远端文档同步滞后可能耗尽核实窗口，此时仍保留未知状态和原超时，不以缓存旁白伪造结论。

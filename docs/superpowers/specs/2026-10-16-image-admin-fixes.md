# Image 测试站管理功能修复

只部署 image.example.com，基线是其实际运行镜像 c2cc4db92af8bc750a2a315093d516e9287c704b7612d9c6a15f49b7aa59bea0。主站不修改、不重启，保留测试站账号、配置与数据。工作区来自运行容器代码，不使用落后的 Image 实验源码构建。

1. 日志仍持久化 UTC，但显式标记时区。读取时将历史无时区 UTC 和新 ISO 时间统一转为 Asia/Shanghai；日期筛选以转换后的北京时间为准，日志 ID 与原文件保持稳定。
2. 账号列表每行的“操作”提供清理图像空间、每天自动清理、手动刷新 Access Token。选择多账号可批量操作。清理沿用预览、确认、快照、复扫；开启自动清理由用户显式选择账号，默认关闭，用户已选定每天仅清理 7 天前图片，未知创建时间和在途账号跳过。任务状态及下次执行时间持久化，重启不重复删除。
3. 设置页 Sub2API 导入将受保护导出的 credentials 完整规范化保存，包含 refresh_token / id_token / expires_at / client_id / 身份字段；保留非凭据来源元数据。JSON 文件导入支持相同格式。重复身份更新同一记录；较旧 token 不覆盖新 token。
4. 自动刷新默认开启：使用 JWT exp 或导入到期时间，提前 24 小时刷新，继续沿用既有后台检查与失败退避；手动刷新专用入口必须使用 refresh_token，而不是仅刷新额度。刷新原子写回所有轮换字段，保留账号设置和在途槽。账号操作 API 使用不可逆身份引用，返回状态而非凭据。

采用独立可维护的页面扩展和对现有 Next 构建产物的最小事件桥接，避免重建整套前端。新增服务只管理账号设置与操作，复用已有 OAuth 与图像清理执行逻辑，不建立第二套刷新机制。

验证覆盖跨北京时间日界线、历史日志删除、完整导入、旧新身份合并、refresh token 轮换、自动刷新默认与手动操作、清理截止时间/未知时间/重启/禁用、鉴权、前端单账号与跨页选择。真实数据以只读预览和界面验证为主，自动清理保持关闭，不为测试删除用户图片。
